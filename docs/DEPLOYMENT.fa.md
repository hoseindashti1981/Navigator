# نصب راه‌نگار روی هاست اشتراکی

این راهنما برای cPanel یا DirectAdmin است. هیچ SSH، Node.js، Docker یا دست‌کاری WordPress لازم نیست. نصب و انتشار واقعی هنوز انجام نشده است.

## ۱. زیردامنه و پوشه‌ها

۱. در بخش Domains یا Subdomains زیردامنهٔ `gps.lineyar.ir` را بسازید. پوشه‌ای مستقل از WordPress انتخاب کنید؛ مثلاً `/home/ACCOUNT/navigator/public`.
۲. بستهٔ `navigator-hosting.zip` را با File Manager در `/home/ACCOUNT/navigator` بارگذاری و استخراج کنید. پوشه‌های `public` و `private` باید کنار یکدیگر باشند.
۳. Document Root زیردامنه باید **دقیقاً پوشهٔ public** باشد. کل Navigator را داخل ریشهٔ عمومی سایت اصلی نریزید. `private`، `database` و `docs` نباید از اینترنت در دسترس باشند.
۴. اگر پنل اجازهٔ تنظیم Document Root نمی‌دهد، از پشتیبانی هاست بخواهید آن را روی پوشهٔ public قرار دهد. جایگزین: محتوای public را در ریشهٔ مستقل زیردامنه قرار دهید، private را در یک پوشهٔ خارج از همهٔ ریشه‌های وب بگذارید و دو مسیر `../private` در ابتدای `public/api.php` را به مسیر خصوصی جدید اصلاح کنید. نام فایل‌ها و مجوزهای خصوصی را در رابط عمومی نمایش ندهید.
۵. مجوز معمول پوشه‌ها ۷۵۵ و فایل‌ها ۶۴۴ است. برای `private/config.php` در صورت پشتیبانی ۶۰۰ یا ۶۴۰ بگذارید. مجوز ۷۷۷ لازم نیست.

## ۲. HTTPS و PHP

۱. برای زیردامنه گواهی معتبر از AutoSSL یا Let's Encrypt فعال کنید.
۲. گزینهٔ Force HTTPS Redirect را فقط برای همین زیردامنه فعال کنید. تنظیمات دامنهٔ اصلی را تغییر ندهید.
۳. PHP ۸٫۲ به بالا انتخاب کنید؛ PDO MySQL و mbstring باید فعال باشند. json و session نیز لازم‌اند. `display_errors` در محیط واقعی خاموش و ثبت خطاها خارج از پوشهٔ عمومی فعال باشد.
۴. مقدارهای پیشنهادی: `memory_limit=128M` یا بیشتر، `max_execution_time=30`، `post_max_size=1M` یا بیشتر. هر درخواست همگام‌سازی حداکثر ۳۰۰ نقطه از رابط و ۴۰۰ نقطه در API دارد. API بیشتر از ۳۰۰ کیلوبایت را نمی‌پذیرد. برای نشست‌ها مسیر قابل نوشتن و پاک‌سازی متعارف PHP کافی است.
۵. اگر HTTPS در پراکسی هاست پایان می‌یابد و PHP درخواست را HTTP تشخیص می‌دهد، از هاست بخواهید متغیر HTTPS را به‌درستی تنظیم کند. برنامه به هدر قابل جعل `X-Forwarded-Proto` اعتماد نمی‌کند. `require_https` در محیط واقعی باید true بماند.

## ۳. پایگاه دادهٔ جدا

۱. در MySQL Databases یک پایگاه **جدید و مخصوص راه‌نگار** و کاربر مخصوص همان پایگاه بسازید. نام کامل شامل پیشوند حساب هاست را یادداشت کنید.
۲. کاربر را فقط به پایگاه جدید وصل کنید. برای نصب می‌توانید مجوز ساخت جدول بدهید؛ بعد از ورود schema، برنامه فقط SELECT، INSERT، UPDATE و DELETE لازم دارد.
۳. با phpMyAdmin پایگاه جدید را انتخاب و `database/schema.sql` را Import کنید. این فایل برای نصب اولیه است؛ دوباره روی پایگاه دارای داده اجرا نکنید.
۴. جداول `users`، `login_limits`، `routes` و `points` باید ساخته شوند. جدول‌های WordPress هیچ تغییری نمی‌کنند.

## ۴. تنظیمات و اولین حساب

۱. در پوشهٔ خصوصی از `config.example.php` نسخه‌ای به نام `config.php` بسازید.
۲. مقدارهای dsn، db_user و db_password را از مشخصات پایگاه جدید تکمیل کنید. نمونه:

```php
'dsn' => 'mysql:host=localhost;dbname=ACCOUNT_navigator;charset=utf8mb4',
'db_user' => 'ACCOUNT_navigator',
'db_password' => 'رمز اختصاصی پایگاه شما',
'require_https' => true,
```

۳. `setup_token` را با یک رشتهٔ تصادفی یکتا و حداقل ۳۲ نویسه‌ای از مدیر رمز عبور جایگزین کنید. مقدار نمونه پذیرفته نمی‌شود. این کلید را در گیت‌هاب، فایل عمومی یا پیام عمومی نگذارید.
۴. `https://gps.lineyar.ir` را باز کنید. فرم «ساخت حساب شخصی» نمایش داده می‌شود. نام کاربری، رمز حداقل ۱۲ و حداکثر ۷۲ بایتی و کلید راه‌اندازی را وارد کنید. برای رمزهای فارسی تعداد بایت از تعداد حرف بیشتر است؛ رمز تصادفی طولانی مدیر رمز مناسب است.
۵. پس از موفقیت، مقدار setup_token در فایل خصوصی را `''` کنید. بعد از ساخت یک حساب، ساخت حساب دوم از API بسته است، حتی اگر کلید باقی مانده باشد. endpoint نصبِ جداگانه یا فایل نصب عمومی وجود ندارد.
۶. خارج شوید و با همان حساب دوباره وارد شوید. داده‌های واقعی را پس از تأیید آزمون‌های زیر ضبط کنید.

## ۵. کنترل پس از نصب

- صفحه و فونت فارسی درست بارگذاری شوند. فایل‌های leaflet.js، leaflet.css و Vazirmatn.woff2 باید همراه بسته باشند.
- درخواست `/api.php?action=list` در مرورگر بدون ورود باید خطای ۴۰۱ بدهد و هیچ مختصاتی نمایش ندهد.
- آدرس‌های `/private/config.php`، `/database/schema.sql` و `/.git/config` باید ۴۰۳ یا ۴۰۴ بدهند. اگر هرکدام قابل دسترسی بود، نصب را متوقف و Document Root را اصلاح کنید.
- روی Apache/LiteSpeed فایل `.htaccess` باید اعمال شود. در Nginx از پشتیبانی بخواهید معادل هدرهای امنیتی فایل public/.htaccess، منع directory listing و منع dotfileها را تنظیم کند. امنیت private به خارج بودن از Document Root وابسته است.
- در Safari به برنامه اجازهٔ مکان بدهید. یک مسیر کوتاه واقعی را در حالت صفحهٔ باز ثبت کنید، مکث و ادامه را امتحان کنید و «پایان و ذخیره» را بزنید.
- تا پیام «مسیر کامل روی سرور ذخیره شد» ظاهر نشده، ذخیرهٔ دائمی را قطعی فرض نکنید. روی دستگاه دوم با همان حساب، مسیر و تمام نقاط را بررسی کنید.
- خروجی JSON و GPX را بگیرید؛ از بخش کتابخانه یک فایل را با نام جداگانه وارد و نتیجه را بررسی کنید.
- آزمون قطع اینترنت و رفرش را طبق TESTING.fa.md انجام دهید. گوشی را هنگام آزمون رانندگی به سرنشین بسپارید؛ کنترل‌ها را در توقف استفاده کنید.

## ۶. سرویس نقشه

پیش‌فرض سرویس عمومی OpenStreetMap با انتساب آشکار است. استفادهٔ شخصی سبک با رعایت سیاست سرویس در نظر گرفته شده؛ SLA یا ظرفیت نامحدود ندارد. دانلود انبوه یا ذخیرهٔ آفلاین کاشی‌ها در برنامه وجود ندارد. با افزایش مصرف یا مسدود شدن سرویس، `tile_url` و `tile_attribution` را به ارائه‌دهندهٔ مجاز تغییر دهید. برای سرویس کلیددار، محدودیت دامنه و سهمیه تنظیم کنید؛ کلید نقشهٔ مرورگری محرمانهٔ سرور محسوب نمی‌شود. از گذاشتن کلید خصوصی در این مقدار خودداری کنید.

## ۷. پشتیبان و بازیابی

۱. به‌صورت دوره‌ای از پایگاه اختصاصی با phpMyAdmin، Export با قالب SQL بگیرید و در محل خصوصی نگه دارید. جدول‌ها شامل موقعیت‌های حساس و هش رمز هستند.
۲. فایل `private/config.php` و فایل‌های برنامه را جداگانه در نسخهٔ پشتیبان خصوصی نگه دارید. تنظیمات واقعی نباید داخل مخزن یا ZIP عمومی باشند.
۳. برای پشتیبان هر مسیر، JSON همهٔ نمونه‌ها و کیفیت آن‌ها را نگه می‌دارد. GPX برنامه نیز نسخهٔ کامل را در افزونهٔ اختصاصی نگه می‌دارد؛ ابزارهای دیگر ممکن است آن افزونه را حذف کنند.
۴. برای بازیابی کامل، ابتدا پایگاه تازهٔ خالی بسازید، SQL پشتیبان را Import کنید، تنظیمات خصوصی را به آن وصل و ورود و یک مسیر را بررسی کنید. روی پایگاه فعلی دارای داده بدون پشتیبان بازگردانی نکنید.
۵. حذف مسیر در رابط، نقاط را واقعاً از پایگاه پاک می‌کند؛ فقط یک شناسهٔ حذف‌شده برای جلوگیری از بازگشت درخواست‌های قدیمی باقی می‌ماند. بازگشت نقاط حذف‌شده فقط از پشتیبان ممکن است.
۶. اگر رمز حساب فراموش شد، از پشتیبانی امن سرور برای جایگزین کردن `password_hash` جدول users با خروجی `password_hash` در PHP کمک بگیرید. گذرواژهٔ ساده یا هش نامعتبر مستقیماً در ستون نگذارید. پاک کردن حساب برای راه‌اندازی دوباره به‌خاطر وابستگی مسیرها توصیه نمی‌شود.

## خطاهای متداول

- «تنظیمات سرور هنوز انجام نشده»: فایل private/config.php ساخته نشده یا مسیر خصوصی اصلاح نشده است.
- «ارتباط با سرور انجام نشد»: مشخصات اتصال، فعال بودن افزونه‌ها و وارد شدن schema را بررسی کنید. متن عمومی عمداً رمز و مسیر سرور را نشان نمی‌دهد.
- «اتصال HTTPS لازم است»: گواهی، آدرس امن و تشخیص HTTPS در PHP را بررسی کنید.
- «تلاش‌های ورود زیاد است»: پنجرهٔ ۱۵ دقیقه‌ای را صبر کنید. محدودیت IP برای جلوگیری از حدس رمز است؛ در شبکه‌های مشترک ممکن است کاربران همان IP را شریک باشند.
- فونت یا نقشهٔ سفید: مسیر فایل‌ها، مجوزها، شبکه و شرایط ارائه‌دهندهٔ کاشی را بررسی کنید. حتی وقتی کاشی‌ها دریافت نشوند، نمونه‌های GPS می‌توانند در صفحهٔ فعال ذخیره شوند.
